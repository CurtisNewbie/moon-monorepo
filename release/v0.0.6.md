# v0.0.6

Release notes for the GitHub release body. Cut from `main` after the version bump; see [`README.md`](./README.md).

## Highlights

- **Name search matches fragments, not whole words.** The manage-files search box splits what you type into terms and requires every one of them to appear somewhere in the file name, in any order. The separators between words do not matter, so `my holiday`, `my-holiday` and `myholiday` all find `my_holiday.mp4`, and `holid` finds `holiday.mp4`. Matching is case-insensitive, short words count, and Chinese names and names like `IMG_2024` or `S01E02` now match. Inside a directory the search stays in that directory; at root it covers every directory.
- **Sort by size, ranking the whole account at root.** While the type filter is File, the Sort dropdown offers Size. The listing opens largest first, and the direction control flips it to smallest first. Files of equal size hold a stable order across pages, so paging neither repeats nor skips one. At root a size sort ranks every file the account owns, not only the ones at the top level, and stays files only.

## Also in this release

- Manage files: picking Size sets the type filter to File, so a directory row never sits in the ranking at zero bytes.
- Manage files: leaving File while sorted by size returns the listing to the order that directory normally opens with. A size sort is not remembered, and no resume offer appears under it.
- Manage files: a search result or a shared link still opens the page that holds the file, including under a size sort.
- Manage files: a Folder Preview checkbox in the toolbar draws a directory's cover picture clipped inside the folder shape, so a row shows what the folder holds. It is off until ticked, and the browser remembers the setting.

## Upgrade

Release manifest: [`db-changes.md`](./db-changes.md) → `v0.0.6`.

### 1. Apply the vfm DDL (required, before deploying vfm)

```sh
source docs/schema/v0.0.6/vfm.sql
```

SQL file: [`docs/schema/v0.0.6/vfm.sql`](../docs/schema/v0.0.6/vfm.sql).

Drops the fulltext index `name_idx` on `vfm.file_info.name`, which no query uses now that the listing matches name substrings term by term. The fulltext index on `vfm.versioned_file` stays, because versioned-file search is unchanged. The statement is **not idempotent** — run it once. No other service has DDL in this release.

No config change: `deploy/docker-compose.yml`, `deploy/backend.env`, nginx and gatekeeper are unchanged.

## Notes

- A size sort runs on the server, both inside one directory and over a set matched by a name keyword; at root it spans every directory.
- Each name-search term scans the requesting user's rows, bounded by `uploader_no_idx`; the leading wildcard rules out an index, as the fulltext match it replaces effectively did.
